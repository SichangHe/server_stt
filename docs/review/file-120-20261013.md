# recorded-file accuracy at 120-second recognition windows
(authored by agents unless marked 🧑)

The file recognizer changed its independent window default from 90 to 120
seconds. The model already batches at most 120 seconds of audio rows per
forward pass; this uses that bound for the file path while the live path keeps
its shorter sliding windows.

commit

The code change is committed as `c375469` (`feat: use 120s windows for file recognition`).

command

```sh
/usr/bin/time -f 'elapsed_s=%e maxrss_kb=%M' timeout 1200s uv run --extra multitalker server-stt /ssd1/sichangheagent/private-artifacts/server-stt/full-ES2004a/ES2004a.mp3 --output output/file-full-120 --language en
timeout 180s uv run --extra multitalker python scripts/score-ami.py /ssd1/sichangheagent/private-artifacts/server-stt/full-ES2004a/reference.tsv output/file-full-120/transcript.json
```

The baseline at commit `09d95f0` was 391/2614 (15.0%) on this same audio and
reference. The new run reduced the speaker-attributed errors by 39.

exploratory results

Before the full-meeting run, the same default change was checked on the
120-second ES2004a crop. The exact scoring output was 67/272 (24.6%) speaker-
attributed errors, unchanged from 90-second windows. A discarded 5–10-second
overlap experiment scored 68/272. Those experiments were reverted; they are
recorded here so the measured alternatives are not mistaken for the delivered
change.
